Kernel

This is the architecture document. The shared loop every other document sits on. Not a product. Not a lane. Not a sales deck.

A stored file is searched for a passage. The passage is copied. A second check confirms the copy. If there is no passage, the turn stops. A named person signs anything that leaves. A better model can be swapped. The sequence stays.

The loop

Five steps, every turn. If no matching passage is in the stored files, the turn stops. If a planted unsupported claim is in the draft, the checker catches it. That is the first acceptance line.

04 / 12

Fifteen invariants

These rules apply to every module and every lane. Changing one is an architecture change, not a prompt tweak.

  1. 01Writer is not the checker

    Different prompt, different role, no shared scratch.

  2. 02No passage, no claim

    A citation is a pointer into a stored file, with a date.

  3. 03Cite or refuse

    Policy version in force on the date of service, or stop.

  4. 04A human sends

    Nothing mails until a name sits on it.

  5. 05Dual-write or refuse

    Overlay ledger and destination ledger, one correlation id.

  6. 06Fit is code

    Fair fit refuses even if the rail is ready.

  7. 07Shadow before gated live

    A prompt cannot promote the mode.

  8. 08No live PHI in the product repo

    Synthetic references only.

  9. 09Refuse is first-class

    Audit writes. Nothing sends. Do not retry with a looser prompt.

  10. 10v1 walls

    No coding agent, outbound file, voice, patient app, or chatbot as the product.

  11. 11Always-on compliance

    Every emit is a control subject.

  12. 12Named roles, allowlisted tools

    A prompt cannot skip a bound control.

  13. 13Three hops or refuse

    Source, overlay, payer. No source binding — not ingested.

  14. 14Fidelity or refuse

    Write-back copies only proven fields. Drift refuses silent overwrite.

  15. 15One operator surface, two form factors

    Console and mobile share the same ids. Neither is a patient app.

Isolation

The drafter does not see the checker’s notes. The checker does not see the drafter’s chain of thought — only the emitted contract and the cited passages. A person may reopen with more documents. The model may not.

06 / 12

Ingest

Named files from the systems already in use, and the people who already run the work. Those files become a hashed corpus — only what the teams may read. Not a new system of record. Not the model’s memory.

07 / 12

Authority

Two modes. Set per agent before the first turn: a person reviews every send, or the work completes unless a flag fires. Standing a team does not widen anyone’s authority. Confidence does not pick the mode. Shadow never writes a destination.

08 / 12

Oversight

The people who already run the work sit first. They can read the draft or the refuse. They send, edit, hold, or flag. Display is required. A recorded decision is not automatically a considered one.

Refuse

If the scoped work cannot be completed from the allowed files, it stops and says so. It does not guess. A person can read the draft or the refuse. Audit writes. Nothing sends.

11 / 12

Proof

A module is not done when the prompt looks good. It is done when the acceptance line is true under a synthetic test file, nothing sends, and refuse paths are tested.

Met on test files

  • No matching passage refuses. Nothing sends.
  • A planted unsupported claim is caught. The drafter is not the checker.
  • An unfounded extract refuses — the value is not a contiguous substring.
  • Thin synthesis refuses — the draft cannot be supported from extracted fields.
  • Emit requires a human name. A verified draft with no name refuses.

Not yet claimed

  • Denials classification on a live 835.
  • A dated policy index on a real book.
  • Three-hop link and proven-field write-back on a client system.
  • An operator console in production.
  • A live book, a BAA, or live PHI in the product repository — none, correctly.
